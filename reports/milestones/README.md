## Decision fields

Record the actual date, input revisions/hashes, completed products, unmet conditions, evidence/access
limits, and one explicit decision: continue, narrow, wait, assign research, or close a branch. Name
the next three actions with owners/dependencies. Identification, novelty, a predetermined mechanism,
or complete archive access are not required success conditions. An unperformed test is incomplete.

## Five-workstream output template

The following is an expected-output checklist schema, not an actual inventory/review. When preparing
`workstreams.md`, give every individual expected output its own status/product or reason.

| Workstream | Expected outputs to account for |
| --- | --- |
| A — Chronology/distribution | Evidence-linked timeline, uncertainty ranges, phase boundaries, and contradiction list. |
| B — Recording comparison | Recording inventory, capture-lineage notes/family tree, annotated transcript, blind review, and reproducible comparison report. |
| C — Historical engineering | Dated signal-path diagrams, assumptions table, and explanation comparison against monitors/reception/geography/recovery. |
| D — Period culture | Dated reference catalog with exact locations, alternative readings, public availability, distinctiveness, and props/equipment/knowledge context. |
| E — Records/human research | Records inventory, gaps, release context, targeted unsent request drafts or neutral interview guides, and source-linked notes. |

Use available, waiting, or deferred only with actual supporting products or precise reasons. A
scaffold is not an available completed research output. Keep source T08 waiting until T07's
completion condition is met; preliminary availability work is a separate research TASK.

## Fixed review and final preservation

Write each decision document and its relied-on basis before review. Preserve a milestone RVW with
ReviewTarget.kind milestone_document, exact document SHA-256/size, immutable document/basis copies,
and fixed record revisions. Reverse lookup attaches the review without editing reviewed content.
Preserved passing snapshots establish historical milestone order; revised current documents need
matching new review. Final handoff-exercise and basis edits must be followed by replacement review
before session snapshotting.

At handoff, save milestone/question, findings/confidence, disagreements/gaps, completed outputs,
hypothesis changes, waits, next three owned actions, and stopped/reopening branches. Back up exact
final notes/registers/session bytes before completion. Missing protection or incoherent publication
remains pending/recovery-required. Routine review does not create an owner-approval pause while
useful authorized work remains. Publication, outreach, and spending retain separate user controls.
