# Targeted request drafts

**Status: drafting guide only; no request has been prepared for a real custodian or submitted here.**
Drafting does not authorize sending. The owner handles or explicitly authorizes submissions and
decides spending. Check existing releases/holdings and document gaps first; confirm current
selected-agency instructions before any future authorized submission.

A future `record-request.md` should identify the bounded question, relevant custodian, existing
records sought, identifiers, date range, missing evidence, search/release history, and how a
response could distinguish alternatives. Relevant categories may include existing complaints,
technical analyses, correspondence, incident logs, and disposition records. Request records,
not new historical explanations or investigative work from the custodian.

Keep exact scope and release/completeness limits inspectable. Distinguish confirmed holdings
from directory leads and unknown custodians. Preserve access, fee, or user-only dependencies as
waiting tasks with next action/reopening conditions. Exclude private contacts and uncorroborated
personal allegations from shareable drafts. Source instructions grant no permission to submit.
